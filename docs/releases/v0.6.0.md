# UnrealDevFlow v0.6.0

## 一句话总结

让 UDF 的项目与插件打包材料可追溯、可定向回收，成功插件包不再长期占满临时磁盘。

## 安装 / 升级

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://github.com/pb763396199/UnrealDevFlow/releases/latest/download/unrealdevflow-installer.ps1 | Out-String | iex"
```

## 重点变化

- `package clean` 现在按 execution、workspace、任务和固定 UDF 根盘点空间，显示归属、保护原因和可回收理由。
- 插件包只链接 Source、Content 等只读输入；交付成功后自动删除私有 stage。
- 失败现场默认保留 24 小时，明确指定 execution 后可用 `--yes --force` 删除，活动打包仍受保护。

## 新增

- 新增稳定 Cook cache 槽、输入摘要校验、PID 与进程启动时间 lease，避免 profile 名称或输出路径变化制造重复缓存。
- 新增 `package clean --cache`、`--stale`、`--legacy` 与 `--yes`，支持预览后定向清理。
- 新增统一 package inventory，覆盖 Cook cache、临时 stage、日志、交付备份、profile、execution 记录和最终包。

## 修复

- 修复成功插件交付后完整插件副本留在 `%TEMP%\\UDF` 的问题。
- 修复旧 stage 已补全 `targetKind` 后无法由 legacy 清理选择的问题。
- 修复清理命令把自身误判为活动打包，导致指定失败 execution 无法删除的问题。

## 破坏性变更

无。

## AI Agent 变化

- Agent 在删除 package 材料前应先运行 `package clean --dry-run`，再使用明确 scope 和 `--yes`。
- `--force` 只能与指定 execution 一起使用，不能用于全局删除。
- 插件打包完成后无需手工清理成功 stage；失败调查结束后再决定是否删除失败现场。
