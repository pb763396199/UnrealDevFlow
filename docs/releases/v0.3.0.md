# UnrealDevFlow v__VERSION__

## 一句话总结

修掉一个会把你主插件仓库暂存区搞脏的缺陷；任务分支名不再带工程名，改成按变更类型分前缀。

## 安装 / 升级

```powershell
__INSTALL_COMMAND__
```

**建议尽快升。** 0.2.0 及更早的版本，`udf task merge --strategy merge` 会在你的主插件仓库里
留下一堆你没做过的暂存改动，`--strategy squash` 撞上冲突时会把仓库丢在半合并状态。

升级不做任何迁移，老任务照常用。

## 重点变化

- **`merge` 不再弄脏你的主仓库。** 这是这一版的主因，细节见下面「修复」。
- **分支名从 `task/<工程名>/<任务名>` 变成 `<类型>/<任务名>`。** 看一眼就知道这次改动是什么
  性质，而不是知道它属于哪个工程。
- **`task create` 新增 `--type`。** 取值 `feature`（默认）/ `fix` / `hotfix` / `refactor` /
  `docs` / `chore`，跟 AES Workflow 协议和这个仓库自己分支用的是同一套词。
- **`--branch` 现在真的可以随便起名。** 工具在主插件仓库的 `branch.<分支名>.udftask` 里记着
  这个分支属于哪个任务，所以 Host 目录丢了之后 `task cleanup` 照样找得回它。这条记录在
  `git branch -D` 时由 git 自己带走。

## 新增

- `task create --type <类型>` 决定默认分支名的前缀，不给按 `feature`。
- 分支台账：建分支时写 `branch.<分支名>.udftask = <workspace>/<task-id>` 到主插件仓库。
- `task cleanup` 在 Host 丢失时按台账精确定位分支，不再只能靠拼名字去猜。

## 修复

- **`merge --strategy merge` 会让主插件仓库的索引和工作区落在 HEAD 后面。** 它用 libgit2 在
  内存里算出合并结果再提交，只移动了分支引用，索引和工作区一个都没碰。结果是合并带进来的
  每个文件都显示成一条你没做过的暂存改动，`git diff --cached` 全是删除。下一次 `task create`
  会被干净工作区检查拦下，看起来像是你自己留了在制品。现在改用 `git merge --no-ff`。
- **`merge --strategy squash` 撞上冲突时把仓库丢在半合并状态。** 冲突判定只看 stderr，而 git
  把 `CONFLICT` 写在 stdout，于是冲突永远判不出来，也就不会 `merge --abort`。现在两个流都看，
  任何失败路径都回滚。
- **`squash` 的提交步骤失败时不回滚已暂存的合并。** `git merge --squash` 按设计只暂存不提交，
  后面那句 `git commit` 一旦失败（钩子拒绝、没配 `user.email`、签名失败），整个合并结果就留在
  你的暂存区里。
- **`squash` 和 `rebase` 会因为未跟踪文件而拒绝执行。** 干净检查把未跟踪文件也算成「工作区
  不干净」。主仓库里只要躺着一个 `workflow/` 或编辑器临时文件，四种合并策略里就有两种用不了。
  现在只看已跟踪文件。
- `task cleanup` 用裸 task-id（不写 `workspace/` 前缀）时查不到台账，分支留在仓库里而命令报
  成功。现在两种写法都查得到。

## 破坏性变更

**默认分支名变了。** 不给 `--branch` 时：

| | 0.2.0 | 0.3.0 |
| --- | --- | --- |
| 默认 | `task/neon-dev1/prefab-save-bug` | `feature/prefab-save-bug` |
| 加 `--type fix` | 不支持 | `fix/prefab-save-bug` |

**已经存在的任务不受影响。** 老分支名带工程名、没有台账，`merge` 和 `cleanup` 走的还是原来
那条按名字反推的路，两条路并存，不需要迁移。

如果你的脚本按 `task/<workspace>/<task-id>` 拼过分支名，这一版之后拼不出来了——改成从
`.udf-meta.json` 的 `branch` 字段读，那里一直是准的。

## AI Agent 变化

`task create` 多了一个 `--type`，**读完需求由 agent 判断这次是哪一类**，别一律用默认值。
五份文档和两份 SKILL.md 都写了取值和规则。

升级后重跑一次安装器，四个 provider 目录里的 skill 会自动更新；手工放的 skill 请自己敲
`udf skill install --global`。

## 校验

这一版实际跑过的门禁：

- `cargo fmt --check`、`cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`、`cargo test` 三条退出码都是 0，90 个用例全过（0.2.0 是 71）。
- 新增一层针对主仓库的审计：每条会动插件仓库的命令跑完，都要满足 `git status --porcelain` 为空、无未合并条目、不留 `MERGE_HEAD` 和 `CHERRY_PICK_HEAD`。覆盖四种合并策略、`create`、`delete`、冲突 squash 和未跟踪文件场景。
- 四条回归测试都做过负向验证：先回退代码修复确认测试会失败，再装回修复确认通过。
- 发布前门禁扩到 12 步，新增脚本编码检查、安装器按 `iex` 方式解析、真跑一遍发布说明生成。
- 编译器版本由 `rust-toolchain.toml` 固定，本地和 CI 用的是同一个。
