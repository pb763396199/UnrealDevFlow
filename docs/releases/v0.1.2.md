# UnrealDevFlow v0.1.2

## 一句话总结

多项目并行和小白工作流版本：新增 workspace/init/start/next/finish，同时修复 merge rebase 与 cleanup 在真实 agent 环境里的安全问题。

## 安装 / 升级

```powershell
__INSTALL_COMMAND__
```

## 重点变化

- 支持一台机器同时管理多个 UE 项目，任务创建时冻结项目、Engine、Hosts 和插件根路径，避免不同 agent session 串项目。
- 新增小白命令，把首次配置、创建任务、下一步提示、验收后合并压缩成 `init/start/next/finish`。
- 修复 rebase 合并方向：保留目标分支已有 commit id，只把任务提交重放到最新 dev 之后。
- 修复 cleanup/delete 顺序和无 TTY 确认问题，解决 agent 环境下无法清理残留分支/worktree 的故障。

## 新增

- 新增 `workspace add/list/doctor/remove`，可注册多个 UE 项目工作区。
- 新增 `init`，自动探测 UE 项目、插件根、Hosts、Engine，并安装 AI skill。
- 新增 `start`，用更短命令创建任务并保存用户原始需求。
- 新增 `next`，根据任务状态只输出下一步动作，降低新用户记命令成本。
- 新增 `finish`，封装验收后的合并向导，但仍要求用户明确合并策略。
- 新增 `workspace/task-id` 任务引用，允许不同 workspace 下存在同名任务。
- 新增回归测试文件 `tests/merge_yes.rs`，覆盖 merge/cleanup/delete 的非交互和历史安全场景。

## 修复

- 修复 `merge --strategy rebase` 会改写目标分支既有提交 id 的严重问题。
- 修复 `merge -y` 在分支分叉确认中仍进入 TTY 对话框的问题。
- 修复 `cleanup -y`、`cleanup --force`、`delete --force` 在无真实终端环境下仍触发确认框的问题。
- 修复 cleanup/delete 先删 Host 目录再删 worktree/branch，导致分支仍被 worktree 占用、重跑又无法恢复的问题。
- 修复 Host 目录已经缺失时无法补删残留本地任务分支的问题。
- 修复多 workspace 下 build/switch/merge/cleanup/delete 依赖当前全局配置，可能串到另一个项目的问题。

## 破坏性变更

- 多 workspace 下短任务 id 如果有歧义会直接报错，需要使用完整 `workspace/task-id`。
- `finish` 仍不会替用户默认选择合并策略；交互或参数必须明确给出策略。

## AI Agent 变化

- 安装版 skill、README、AGENTS、CLAUDE 文档同步更新为 workspace + 小白命令流程。
- agent 后续操作优先读取任务 `.udf-meta.json` 中冻结的 workspace 上下文，不再依赖当前全局默认配置。
- 非交互参数 `-y/--force` 已用回归测试约束，适合 Codex/Claude 这类无真实 TTY 的执行环境。
- 发布过程中误触发的 `v0.0.2` draft/tag 已撤回，最终公开版本为 `v0.1.2`。
