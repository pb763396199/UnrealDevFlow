# UnrealDevFlow v0.5.0

## 一句话总结

把 Unreal 项目打包从一次性命令升级为可复用、可追溯、贴近编辑器原生行为的任务级发布流程。

## 安装 / 升级

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://github.com/pb763396199/UnrealDevFlow/releases/latest/download/unrealdevflow-installer.ps1 | Out-String | iex"
```

安装器会把 `udf.exe` 和全局 skill 安装到 `%USERPROFILE%\\.unrealdevflow\\bin`，并更新 User PATH。

## 重点变化

- 普通任务明确只打项目包，插件包和 Installed Build 改为显式高级入口。
- 每个 task 保存固定打包配置，日常开发和完整发布分别使用 `iterate` 与 `full` Cook 模式。
- 打包计划默认读取项目自身的 Packaging、Cooker、地图和平台设置，只有明确覆盖时才改变原生行为。
- 输出目录、包名、版本 lineage、磁盘空间、临时目录和交付恢复都有可查询记录。

## 新增

- 新增 `package configure`、`package plan`、`package check`、`package project`、`package status`、`package clean` 和 `package recover` 的任务级配置与执行闭环。
- 新增项目副本打包和插件排除能力，支持在副本中禁用无法参与打包的 MCP 插件，不修改主项目。
- 新增 manifest 交付保护，保留用户文件和外部 Junction，只回收 UDF 自己创建的文件。
- 新增任务路由持久化，任务 Host、主项目路径变化或 state 缺失时仍能安全清理 Junction。
- 新增主插件仓库脏状态边界：未跟踪临时文件不阻止建 task，已跟踪修改仍会阻止建 task。

## 修复

- 修复 task 删除 Host/worktree 后主项目残留悬空 Junction 的问题。
- 修复 Junction 清理依赖 state 或当前配置，导致路径变化后漏清理的问题。
- 修复高级打包失败时误删既有输出、残留临时目录或无法恢复的问题。
- 修复旧的顶层 `package run` 入口仍可能被误调用的问题。

## 破坏性变更

- `package run` 已移除。
- 插件包和引擎 Installed Build 不再作为普通 `package project` 的隐式路径，必须显式使用 `package advanced plugin` 或 `package advanced engine`。
- 已跟踪的主插件仓库修改仍不能直接创建 task；请提交、暂存恢复或使用明确的基线参数。

## AI Agent 变化

- Agent 应先为 task 固定打包配置，再执行 `package plan` 和 `package project`。
- 未明确要求插件包或引擎包时，只调用项目包路径，不自行扩展验证范围。
- 默认日常验证使用 `iterate`；完整发布必须显式保存 `full` 配置。
- `task create` 可以容忍主插件仓库中的未跟踪 workflow/output 文件，但会从当前 `dev` 提交创建 Host，并明确提示这些文件不会进入 Host。
