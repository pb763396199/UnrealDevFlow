# UnrealDevFlow v__VERSION__

## 一句话总结

UnrealDevFlow 现在具备面向发布的 Package 命令体系：项目、插件、插件集合和源码引擎都能先检查、看计划，再执行并追踪真实制品。

## 安装 / 升级

```powershell
__INSTALL_COMMAND__
```

升级后无需迁移现有 workspace 和任务。原有 `build`、`task`、`workspace` 命令保持兼容。

## 重点变化

- 新增顶层 `package` 分类，覆盖项目发布打包、插件隔离编译、插件集合发布和源码引擎 Installed Build。
- `check`、`plan`、`status` 在 Build 与 Package 中使用统一职责：检查能否执行、展示将执行什么、读取已经启动的执行。
- Package 的查询命令不创建 execution ID，也不会覆盖最近一次真实执行记录。
- 插件发布使用独立短路径暂存工程和 `-NoMutex`，不会占用正常 Host 编译使用的 UE 全局 Mutex。
- Package 制品带执行记录、日志、manifest 和受管清理边界，可追踪也可安全回收。

## 新增

- `udf package check project|plugin|engine`：只返回 readiness、检查项、诊断和下一条执行命令。
- `udf package plan project|plugin|engine`：只返回步骤、参数、输出和确定性计划摘要。
- `udf package project`：通过 BuildCookRun 构建、Cook、Stage、Package 和 Archive 项目。
- `udf package plugin`：为插件生成 Editor Development、Game Development、Game Shipping 三阶段隔离编译。
- `udf package engine`：通过 BuildGraph 生成 Windows/Linux Installed Build。
- `udf package status <execution-id>` 与 `udf package clean <execution-id>`：查询真实执行并清理它记账的可再生制品。
- 插件集合支持：传入没有同名描述文件的集合目录时，递归发现内部插件并保持相对目录结构。
- `udf workspace inspect`、`udf build plan` 与 `udf build engine`，补齐工作区来源和构建计划查询能力。

## 修复

- 修复 Package 隔离插件编译错误触发 UE 全局 Mutex 的问题；所有隔离阶段固定使用 `-NoMutex`。
- 修复深层 Host 路径导致 UBT action path 超过 Windows 260 字符限制的问题，暂存目录改为受管短路径。
- 修复普通单插件因无关目录存在同名 `.uplugin` 而失败的问题；冲突只在请求集合子树或实际依赖多候选时拒绝。
- 修复查询命令污染最近一次执行记录的问题；旧 planned/ready/blocked/deferred 记录不会冒充真实执行状态。
- 修复 Package clean 可能触及受管目录外路径的风险，越界目标会被拒绝并保留文件。

## 破坏性变更

无。新增命令不改变既有 `build task`、`build project`、任务创建、切换和合并行为。

`check`、`plan`、`status` 的输出职责已统一；依赖旧版实验性 Package 查询字段的脚本需要按新字段读取。

## AI Agent 变化

- Agent 在启动耗时构建前可先调用 `check`，遇到 `deferred` 时等待 Mutex，不需要尝试并发绕过。
- Agent 可用 `plan` 审核完整 UE 命令、步骤数、输出路径与 Mutex 参数，而不产生执行副作用。
- 只有真实执行会产生 execution ID；后续 `status` 和 `clean` 必须围绕该 ID 工作。
- Workspace、Task、Build、Package、Skill 的二级命令按统一词义归类，降低跨类别切换时的理解成本。
