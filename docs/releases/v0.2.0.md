# UnrealDevFlow v__VERSION__

## 一句话总结

命令行从 `unrealdevflow` 改名为 `udf`，20 个平铺命令收成 `workspace` / `task` / `build` / `skill` 四个组，每个命令都能输出 JSON，帮助文本全部改成中文。

## 安装 / 升级

```powershell
__INSTALL_COMMAND__
```

安装器会把新的 `udf.exe` 放进原来的目录，并**删掉所有还叫 `unrealdevflow` 的旧入口**——
包括 `unrealdevflow.exe`、手工放的 `unrealdevflow.cmd` 垫片，以及以前的安装器留下的
`unrealdevflow.installed-<日期>.exe`。安装目录和 PATH 项都没有变，不需要你手工调整环境变量。

升级后请再确认一件事：**旧命令必须已经失效**。开一个新窗口敲 `unrealdevflow --version`，
应该提示找不到这个命令。还能跑出旧版本号，说明你的 PATH 上还有别处的副本。

## 重点变化

- **命令名从 13 个字母变成 3 个。** `udf` 在仓库里早就是既成约定（`.udf-meta.json`、`UDF_VERSION_LONG`），这一版把可执行文件名也对齐了。
- **顶层从 20 个命令收成 4 个组。** 先想「我在操作什么」，再想「做什么」，不用再靠翻 `--help` 找命令。
- **`build task` 和 `build project` 并列之后，语义反转的问题消失了。** 原来的 `build` 编任务宿主、`build-project` 编主项目，名字读起来是反的。
- **所有命令都支持 `--format json`。** 写操作返回它做了什么，不是只返回成功——`task cleanup` 会分别报告 worktree、分支、Host 三项各自成没成，「部分清理」不会再被报告成成功。`--dry-run` 也返回结构化的预览数据，机器读得到要删什么、要合什么。
- **帮助文本全部是中文。** 22 个叶子命令的说明、参数和取值都改了，连 `Usage:` / `Commands:` / `Options:` 这些段落标题也换成了「用法」「命令」「选项」。参数给错时命令行库本身吐的报错仍是英文。

## 新增

- 统一的 JSON 信封：`{command, ok, data, error, messages}`，成功和失败都是同一个形状，一条命令只吐一个文档。
- `workspace status`：每个 UE 项目当前挂着哪个任务（原顶层 `status`）。
- `task create` 不给 `--prompt` 时，自动把描述存成原始需求。
- `build status` 省略任务引用时按最近动过的任务解析，跟 `build check`、`task next` 一致。
- `task switch` 切到一个当前已经在上面的任务时，会先说明「已经在这个任务上，下面的重建是幂等的」，不再让你分不清有没有真的切换。

## 修复

- **断链 Junction 不再挡住 `switch`。** 任务被 `cleanup` 之后，UE 项目里会留下指向已删目录的 Junction，下一次 `switch` 直接失败在「文件已存在」。根因是三层判定都跟随重解析点，所以自称能自愈的断链处理从来没有生效过。
- **`build gate` 在没配置过的机器上也能用。** 它只做字符串判定、不读任何配置，而 hook 和 wrapper 正是在还没跑过 `workspace init` 的环境里调它。
- **`build gate` 现在会拦下 `--mutex no-mutex`。** 此前它放行这条命令，而文档写的规则是不许这么绕过互斥锁。
- **安装器不再谎报成功。** 装 skill 那一步以前敲的是已经不存在的子命令，失败了却仍打印「装好了」；从源码构建失败时也会照样把上次留下的旧二进制装出去。两处现在都检查退出码，失败就中断。
- `list` / `status` / `aw-status` 在 `--format json` 下不会再输出两个 JSON 文档。

## 破坏性变更

**这一版所有旧命令名都不再存在，也没有保留别名。** 升级后请照下表更新脚本。

| 旧命令 | 新命令 |
| --- | --- |
| `unrealdevflow init` | `udf workspace init` |
| `unrealdevflow configure` | `udf workspace add`（`configure` 已删除） |
| `unrealdevflow workspace add/list/doctor/remove` | `udf workspace add/list/doctor/remove` |
| `unrealdevflow status` | `udf workspace status` |
| `unrealdevflow start` | `udf task create`（`start` 已删除） |
| `unrealdevflow create` | `udf task create` |
| `unrealdevflow list` | `udf task list` |
| `unrealdevflow next` | `udf task next` |
| `unrealdevflow switch` | `udf task switch` |
| `unrealdevflow merge` | `udf task merge` |
| `unrealdevflow finish` | `udf task finish` |
| `unrealdevflow cleanup` | `udf task cleanup` |
| `unrealdevflow delete` | `udf task delete` |
| `unrealdevflow build` | `udf build task` |
| `unrealdevflow build-project` | `udf build project` |
| `unrealdevflow build-check` | `udf build check` |
| `unrealdevflow build-gate` | `udf build gate` |
| `unrealdevflow build-status` | `udf build status` |
| `unrealdevflow skills install/list/remove` | `udf skill install/list/remove` |

另外两条行为变化：

- **`task switch --project` 只接受任务自己绑定的项目。** 任务绑定的项目取自元数据里冻结的
  `TaskContext.default_project`；指向别的项目会被拒绝，并且拒绝前不会改任何 Junction。
  `task switch main` 不受这条约束。
- **最低 Rust 版本提到 1.89**（受控构建用的 `ipc-lock` 要求）。用预编译包的用户不受影响。

**没有变的东西**：配置目录仍是 `~/.unrealdevflow/`，安装目录仍是 `~/.unrealdevflow/bin`，
User PATH 项不变，环境变量 `UNREALDEVFLOW_CONFIG_DIR` 和 `UNREALDEVFLOW_UE_ENGINE_ROOT` 不改名。
安装命令的 URL 也没变。

## AI Agent 变化

**装在 AI provider 目录里的 SKILL.md 会随安装器一起更新。** 装完之后 `.codex`、`.agents`、
`.claude` 和 opencode 四个目录里的说明书都是新版，教的是新命令，而且**全文改成了中文**，
包括 agent 用来判断该不该触发的那句 description。

如果你是手工放的 skill、没走安装器，请自己敲一次：

```powershell
udf skill install --global
```

不做这一步的话，agent 会继续发旧命令，而旧命令这一版直接报 `unrecognized subcommand`
且不指路——它会连撞几次才可能反应过来。

命令分组之后对 agent 也更好用：22 个叶子全部支持 `--format json` 并返回真实数据，失败时
信封里的 `command` 报的是叶子名（`task switch`）而不是组名，调用方分得清是哪一步出的事。

## 校验

这一版实际跑过的门禁：

- `cargo fmt --check`、`cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`、`cargo test` 三条退出码都是 0，71 个用例全过。
- 在真实 UE 项目（4 个主插件、6 组排列组合）上跑了端到端冒烟，含一次真实编译和一次 UBT 工程文件重生成，收尾把环境逐字节还原。
- 安装器的删旧留新、构建失败中断两条行为，按用户机器的真实目录形态在隔离目录里实测过。
- 137 条文档命令示例逐条对着 `--help` 核过参数，27 个帮助页扫过没有残留的英文骨架。
- 人工核对清单 10 条全部通过。
